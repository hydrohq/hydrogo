# ADR-0018: File-based theme bundles and safe slot renderer

- **Status:** Accepted
- **Date:** 2026-09-10
- **Related decisions:** [ADR-0010](0010-sdk-lifecycle-and-edition-manifest.md), [ADR-0016](0016-structured-page-blocks-and-theme-slots.md)

Theme bundles consist of `theme.json`, `layouts/base.html`, and asset files declared in the manifest under `themes/<name>/`. The manifest is validated at startup; the theme name, slots, and asset paths cannot escape the allowlist. `..`, absolute paths, and Windows separators are rejected.

Core does not load or execute Go code from the theme folder. The `html/template` based layout only receives `template.HTML` slots generated by the trusted application. Theme selection is the responsibility of the build/edition or validated startup configuration; an arbitrary theme path is not selected via user input.

Theme loading validates the asset inventory and the layout file. Thus, if the required asset inventory is missing during a blue/green deployment transition, the application fails at startup; it does not silently produce missing assets during runtime.
