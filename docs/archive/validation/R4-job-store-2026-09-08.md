# R4 durable job lease store validation

**Date:** 2026-09-08  
**Roadmap:** R4 shared transaction/hook/event/job contract kit  
**Status:** SQLite/PostgreSQL lease backend, News durable queue adapter, production worker bootstrap, and dialect-free bounded hook fixture succeeded.

`internal/jobs/sqlstore` provides idempotent enqueue, bounded capacity, token-owned claim/ack/nack, and expired lease reclaim behavior with the SQLite/PostgreSQL placeholder contract. Migration `202609080013_jobs` carries the same schema and checksum metadata for both dialects. The current bounded in-process queue of News is preserved backwards; `cmd/hydro serve` production scheduler bootstrap uses the durable backend.

Executed checks:

```text
go test ./internal/jobs/... ./migrations ./...
go vet ./...
```

SQLite and PostgreSQL contracts validate duplicate payload conflict, incorrect worker rejection, reclaim post-nack, and deletion post-ack. The PostgreSQL test runs in the CI service with `HYDRO_TEST_POSTGRES_URL`.

In the CI run where `HYDRO_TEST_POSTGRES_URL` is defined, the same lease scenario is also run on PostgreSQL; if the variable is missing in the local environment, the test is deliberately skipped. `sqlstore.Queue` is validated with `news.DurableQueue` in a compile-time contract test.

`internal/hooks.Dispatcher` validates the shared event contract that both modules can use: successful event IDs are processed idempotently only once, a failed handler can be retried, and the dedup window is kept bounded.
